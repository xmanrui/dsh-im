# 会话目录隔离

会话目录隔离让**一个对话在自己的目录里工作**：新会话创建前，插件会在该对话的基工作区下按会话标识建一个目录，把该对话的工作目录切过去，再创建 Harness Session。模型读写文件、执行命令的落点因此按对话分开，多个人在同一个机器人上并行使用时不会互相覆盖文件，也不必为每个对话手工建目录。

本功能**默认关闭**；未开启时插件的行为与开启前完全一致。

## 开启

**默认对整个渠道生效**：在该渠道数据目录的 `workspaces.json` 顶层加一个 `conversationDirectory` 段落，该渠道的**所有机器人**都会启用，不需要填写 botId。

也可经管理 RPC 写入渠道默认（无 botId）：`bot.conversation-directory.default.set`，payload 为 `{ "config": { "enabled": true, "strategy": "per-conversation", "prefix": "conv-" } }`；`{ "config": null }` 清除渠道默认。

**Web 设置页（飞书渠道）**：更多设置里有一个 会话目录页签；每个机器人卡片内有「会话目录隔离」。未覆盖时显示「继承渠道默认」；打开开关写入 per-bot 覆盖。隔离开启时「当前工作区」锁定。

```json
{
  "conversationDirectory": { "enabled": true }
}
```

- 文件位置：`~/.dsh/integrations/dsh-<渠道>/workspaces.json`，例如飞书是 `~/.dsh/integrations/dsh-feishu/workspaces.json`。
- `strategy` 与 `prefix` 可省略，默认分别为 `per-conversation` 与 `conv-`。
- **改动后必须重启 DSH**：插件只在启动时读取该文件；运行中手改不会生效，而且之后任意一次落盘都会把未加载的改动覆盖掉。

如果只想让**个别**机器人启用（或让某个机器人在渠道整体启用时单独关闭），再用按机器人的覆盖：

```json
{
  "conversationDirectory": { "enabled": true },
  "conversationDirectories": {
    "<botId>": { "enabled": false }
  }
}
```

按机器人的值优先于渠道值；两者都没有时该机器人不启用隔离。

开启后只影响**之后新建**的会话：已有会话继续用原来的工作目录，发送 `/new` 即可进入隔离目录。

## 策略

| 策略 | 目录 | 说明 |
| --- | --- | --- |
| `per-conversation`（默认） | `<基工作区>/<前缀><会话标识>-<摘要>` | 一个对话固定一个目录；反复 `/new` 复用同一目录，不会层层嵌套 |
| `per-session` | 同上，末尾再加时间戳 | 每次新建会话都换一个新目录；旧目录保留，插件不会删除 |

## 前缀与策略改动何时生效

在设置页修改**前缀**或**策略**后，**无需移除并重新添加机器人**。已运行的 Session 工作目录在创建时即固定、无法中途更改，因此改动在该对话**下一个新 Session** 时生效：发送 `/new`（或会话已失效、下一条消息自动新建 Session）时，插件检测到落盘的目录记录与当前设置不符，会在**同一基工作区**下按新设置重新派生一个目录并原子切换过去，旧目录及其中的文件**原样保留、绝不删除**。

- 在 `per-conversation` 策略下，机器人身份、配置文件位置和基工作区不变时，把前缀改回原值后，下一个新会话会**重新指回原目录**，之前的文件还在。
- `/workspacelist` 按已登记的隔离目录及其历史记录隐藏会话目录，改过前缀的旧目录也会隐藏；用户自行创建的同前缀目录不受影响。`/workspacelist all` 显示全部目录。
- 手动编辑 `workspaces.json` 仍需重启（插件只在启动时读取该文件）；本节仅指设置页 / 管理 RPC 的在线改动。

## 目录命名

目录名由配置文件路径、机器人 ID 和会话标识共同推导；这些信息不变时，重启后重新计算结果一致：

- 会话标识中的 `:` 等文件系统非法字符替换为 `-`；
- 因为替换是有损的（`p2p:a-b` 与 `p2p:a:b` 会得到相同的可读部分），名字末尾附加一段由机器人身份和**原始**会话标识算出的 16 位摘要，以区分会话和机器人；
- 名字总长限制在 100 字符内，过长时截断可读部分并保留摘要；
- 前缀默认为 `conv-`，可在设置中改为 1–32 位字母、数字、下划线或连字符。

## 与工作区命令的关系

开启隔离后，**工作区由对话自动派生**，所有手动改工作区的入口均不可用：

| 命令 | 开启隔离后 | 关闭隔离后 |
| --- | --- | --- |
| `/workspace` `/ws` | **不响应** | 切换 bot 默认工作区 |
| `/conv` `/conversation` `/thread` | **不响应**（含设置/清除/无参展示） | 查看/设置/清除对话专属工作区 |
| `/session <ID>` | 仅可绑定**当前对话有效工作区（隔离目录）内**的会话；不改任何工作区配置；其他工作区的会话拒绝绑定 | 可按原逻辑对齐工作区 |
| `/workspacelist` | 可用；默认**隐藏**自动创建的会话目录 | 同上 |
| `/workspacelist all` | 显示包括会话目录在内的全部工作区 | 同上 |
| `/new` | 可用（准备/复用隔离目录） | 同左（未开启时无目录步骤） |
| 设置页「工作区」 | **锁定**，不可手动改 | 可编辑 |

Store / RPC 层同样拒绝 `workspace-manual-edit-disabled`，防止绕过命令层。

关闭隔离后，`/conv N` 与 `/workspacelist`、`/ws`、无参数 `/conv` 显示的工作区编号一致；对话已有专属工作区不会改变编号顺序。

## 失败时的行为

目录创建或目录配置持久化失败（例如权限不足、磁盘满、路径过长）时，插件回退到原工作区，并在 `/new` 的回执中说明原因，例如「会话目录未生效：无法创建目录（权限或磁盘空间不足）；本次仍在原工作区运行」。日志中同时记录一条警告。

## 关闭与回滚

删掉 `conversationDirectory` 段落（或把 `enabled` 改回 `false`）并重启即可。关闭后：

- 不再创建新目录；
- 已创建的目录与其中的文件**保持原样**，不会被删除；
- 已按会话目录运行的对话继续使用该目录（它已成为该对话的工作区覆盖）；发送 `/conv clear` 可让其回到 bot 默认工作区。
