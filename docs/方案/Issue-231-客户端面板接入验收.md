## 目录选择专项

默认 macOS 模式确认调用了宿主的原生目录选择器；浏览器原设置页和桌面嵌入路径行为一致。当前自动化未能单独控制 `osascript` 的系统选择窗口，因此不宣称验证了原生系统窗口的最终目录确认。

为验证同一依赖在真实桌面面板内的目录读取能力，临时使用宿主已有的 browse 后端及客户端目录浏览器：

1. 禁用默认 `directory-picker` 自动装配，再同时插入 browse host 和 browse UI。仅覆盖入口的 `name` 不会替换原插件，首次临时配置导致两种 UI 同时注册；改为显式禁用自动装配后启动正常。
2. 从已接入微信账号打开目录选择器，成功显示现有目录、面包屑、可编辑路径和选择按钮。
3. 输入当前代码仓库的绝对路径并前往，成功列出 `docs`、`plugin-src`、`test` 等子目录。
4. 取消后原机器人工作区保持不变。
5. 将 profile patch 按备份逐字节恢复，最终仍使用默认系统目录选择模式。

原生取消/降级路径与浏览路径另有既有 workspace-editor 自动化覆盖。本次没有为测试改写生产目录选择逻辑。

临时消费插件已通过官方 CLI 移除；临时目录 patch 已恢复；隔离旧版测试服务和一次性认证跳转服务已停止；测试触发的系统目录选择进程已清理。没有改动旧的 `/Applications/DSH Desktop.app`（`2.0.3`），也没有停止原有 3080 Web 服务。

最终重新从「应用程序」启动目标桌面端，原“设置 → IM机器人”恢复，临时验收入口已消失；中文默认微信面板显示 `DSH-IM v4.21.2` 和 `1 / 1 在线`。默认 profile patch 与备份一致，临时消费插件不再存在于依赖和 bundle 列表中。

## 后续：保留用户日常使用的桌面侧栏入口

用户随后明确要求侧栏入口保留，不能在测试后移除。为此另装了本地持久接入插件 `dsh-im-desktop-panel`，源码独立保存在 `~/.dsh/local-plugins/dsh-im-desktop-panel`，通过官方 CLI 链接到 tauri profile 并加入 bundle 列表。它不修改应用签名文件，也不依赖临时测试目录。

该插件提供「DSH-IM」侧栏入口与完整面板，不包含验收控制按钮。只有桌面 iframe 启用侧栏并隐藏重复设置入口；同一 host 的普通浏览器仍保留「设置 → IM机器人」。旧版缺少 `dshImClient` 服务时，可选接入不会激活。

安装后重启真实桌面端，确认侧栏「DSH-IM」可见且可打开，面板显示 `DSH-IM v4.21.2`、默认微信与 `1 / 1 在线`。同时打开 3081 的普通浏览器，原 IM 设置入口与面板仍正常。此本地接入按用户要求保留，后续清理不得自动移除；它尚非上游桌面端内置发布版本。

随后按用户要求，将侧栏显示名称改为与设置一致的「IM机器人」，通过 `ctx.locale.bind('dsh-im')` 复用设置入口的翻译（英文为 `IM bots`）。已在真实桌面界面确认标签更新，点击可打开正常面板；入口继续保留。

提交代码时，将已安装插件的同一份实现纳入 `integrations/desktop-panel`，并附独立安装说明。已安装的本地副本及 profile 配置保留不动；主 npm 包仍不包含这个可选桌面接入目录。
