## 3. 随后补一个最小修复

从合并后的 main 建立 `codex/fix-feishu-quoted-mention`，修改 `src/channels/feishu/bridge.mjs`。

根因：`accept()` 调用 `isBareMentionMenuRequest()` 时没有排除引用消息；实际发送菜单的 `#handle()` 分支却额外要求 `!hasReply`。因此鉴权判定覆盖了实际不会打开菜单的消息。

采用以下局部修改：

- 给 `isBareMentionMenuRequest()` 的选项增加 `hasReply = false`，在已有图片、文件判断中同时排除引用：`hasImages || hasFiles || hasReply` 时返回 `false`。
- `accept()` 使用已解析的 `commandMessage`，传入 `hasReply: hasReplyReference(commandMessage)`。
- `#handle()` 传入已经计算好的 `hasReply`，让两个入口完整使用同一套菜单判定。
- 继续复用 `hasReplyReference()`，不要另外根据原始 `parent_id` 或 `root_id` 编写引用识别规则，以保留现有父消息选择和根消息自身排除逻辑。

不放宽命令权限：没有引用的单独提及仍按菜单命令鉴权；带引用的消息回到已有普通聊天处理路径。转发卡片文本提取逻辑保持原 PR 的实现。

预计修改范围是上述源码、现有 `test/channels/feishu/bridge.test.mjs`、必要的 `lib/` 构建产物，以及按仓库惯例补充的变更说明。
