# Issue #250：飞书状态写入队列恢复与实测

日期：2026-09-23。问题：[飞书状态文件写入失败后，后续消息持续失败](https://github.com/xmanrui/dsh-im/issues/250)。

## 修复

`StateStore.#persist()` 原来直接将可能拒绝的写入 Promise 保存为下一次写入的前置条件。一旦 `mkdir`、`writeFile` 或 `rename` 失败，后续 `.then()` 的写入回调全部跳过，磁盘恢复后也无法自行恢复。

沿用钉钉等渠道的现有实现，将本次 `operation` 和内部 `#writeQueue` 分开：调用方继续等待并接收本次写入错误，内部队列在成功和失败时均恢复为可继续排队的状态。保持原有串行写入、快照、原子替换和消息去重语义；不新增依赖、配置或重试机制。同步更新 Host 构建产物和更新日志。
