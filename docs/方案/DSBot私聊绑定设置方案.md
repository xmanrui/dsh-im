# DSH IM 绑定 DS Bot 私聊方案

日期：2026-10-21。本文描述最终实现边界。

在机器人卡片的“更多设置”中增加“绑定bot”页签，紧接“投递设置”。用户选择 DS Bot 和已聊过的私聊对象，保存后即可使用该 Bot 的会话，并自动获得会话双向同步能力。无需手动修改工作目录、填写会话 ID 或开启同步开关。

## 产品边界

- 第一版只支持私聊，不支持群聊、频道、话题和线程。
- 新功能独立于“投递设置”：不要求先创建投递目标，不读取投递目标作为绑定候选，不增删或改写投递目标。
- 原“投递设置”的界面、私聊双向同步开关、保存配置和主动投递功能保持原有行为。绑定和解绑都不修改其同步开关。
- “绑定bot”自动开启双向同步，不另设同步开关。即使普通投递同步关闭，绑定的私聊仍可同步。
- 同一私聊同时存在普通同步和 Bot 绑定时，发送层合并为一次同步，避免重复消息；普通同步配置仍完整保留。解绑后按原配置处理后续普通会话。
- 只复用底层私聊路由、会话解析、发送、来源识别和同步协调器，不复制消息引擎，也不复制 DS Bot 的长期记忆机制。

## 页面

页签顺序：**通用 → 投递设置 → 绑定bot → 访问设置 → 渠道原有页签**。

页面沿用现有字体、表单、按钮和列表样式：

1. 进入时检测 DS Bot，并提供“刷新”。
2. 表单只有“DS Bot”和“私聊对象”两个选择项，以及“保存绑定”。
3. Bot 选项、选中值和绑定结果均显示 DS Bot 原有 logo 与名称，包括原有形状、颜色或上传的头像。无自定义头像时按原规则生成默认头像。
4. 已绑定列表展示 Bot logo、名称、私聊对象和“解除绑定”。
5. 没有私聊记录时提示先给当前 IM 机器人发一条私聊消息，再刷新。不引导创建投递目标。
6. 同一 IM 账号内，DS Bot 和私聊对象只能各参与一条绑定。已绑定项退出可选列表，保存后清空选择；修改配对须先解绑。不同 IM 账号的绑定互不占用选项。
7. 没有剩余选项时禁用相应选择框和保存按钮，提示解绑后可重新选择；刷新会清除已被其他页面绑定的过期选择。

绑定页每次进入页签时读取最新 Bot 名称、头像和绑定状态，不设置定时检查，也不在窗口焦点或可见性变化时额外读取。保留手动“刷新”按钮，绑定、解绑完成后刷新结果。更新覆盖候选、选中值和已绑定列表，仍按稳定 Bot ID 保存绑定关系。

侧边栏中的已绑定会话在 DSH 原生 `sidebar.session.row.leading` 图标位置显示 Bot 原有头像，位于已有渠道 logo 之前。按当前 Session ID 匹配，不依赖会话名称；保留 DSH 原有工作状态指示。名称沿用 DS Bot 的原生会话重命名事件，头像在首次加载、返回 DSH 窗口或页面重新可见时读取一次，绑定、解绑完成后立即更新。窗口可见或隐藏时均不做定时检查。解绑或读取时发现 DS Bot 不可用则清除会话头像。

私聊候选来自该账号的入站会话记录，并与已保存的绑定取并集。必须通过渠道现有路由规则确认私聊，群聊不能仅改 `kind` 就成为候选。当前记录没有联系人姓名时显示适当缩略的地址，不读取另一页面的目标名称作为依赖。

## DS Bot 检测

检测当前 DSH Host 上的 `ds-bot`，不通过固定目录判断是否安装。

| 状态 | 页面行为 |
| --- | --- |
| 检测中 | 显示加载提示，暂不允许保存 |
| 未安装 | 提示到 DSH 插件管理安装，然后刷新 |
| 已安装但未启用 | 提示启用后刷新 |
| 正常、没有 Bot | 提示先在 DS Bot 创建机器人 |
| 正常、有 Bot | 展示表单 |
| 接口失败、超时或不兼容 | 提示暂不可用，不误报为未安装 |
| 只读或由其他 Host 管理 | 提示在管理它的 Host 绑定 |
| IM 渠道连接远程 Harness | 提示本功能需要当前 Host 的会话 |

不自动安装或启用插件。不可用时保留已保存关联供查看和解除。

`createDsBotClient` 在 Host 插件管理能力可用时查询 `pluginManager.listBundles()`，再通过现有 `connection.createSharedFetchHandler('/api')` 访问已注册的 DS Bot `/api/bot` `state` 接口，复用现有 owner peer。无需新端口、凭据、文件监听或第二个 DS Bot 运行实例。

适配基线为 DS Bot 0.1.7。只提取稳定 ID、名称、当前 Session、头像及历史分段 ID；前端只收到身份和头像字段。上传头像只接受受限大小的 raster data URL，不加载任意外部图片。

## 渠道范围

当前公共“投递设置”页面覆盖的 11 个渠道均使用同一绑定页面及服务：

| 渠道 | 可绑定记录 |
| --- | --- |
| 微信、飞书、钉钉、企业微信、企业微信应用、QQ | 各渠道已建立的用户私聊 |
| Slack | direct 私信，不含频道或线程 |
| Telegram | direct 私聊，不含群组或 Topic |
| Discord | direct 私信，不含服务器频道 |
| WhatsApp | 用户私聊，不含群组 |
| iMessage | direct 记录且原生 GUID 为单人聊天标记 |

旧版 iMessage 运行时可能把群聊也记作 direct，因此还需检查 `iMessage;-;…` 或 `any;-;…` GUID；拒绝 `;+;` 群聊及无法确认的 GUID。邮箱和 Matrix 当前没有公共投递设置入口，本次不为它们新增页面。

## 独立保存绑定

关系为：**IM 账号 + 私聊 conversationKey → DS Bot 稳定 ID → 当前 Session**。

名称和当前 Session 都可能变化，不能作为持久身份。复用现有 `BotWorkspaceStore` 文件及串行写入队列，在版本 4 增加独立部分，版本 5 允许以 null 记录已经确认但已解绑的私聊：

```json
{
  "version": 5,
  "dsBotBindings": {
    "im-account-id": {
      "private-conversation-key": "stable-ds-bot-id"
    }
  }
}
```

原有 `deliveryTargets` 结构保持原样；版本 3 的普通同步、版本 4 的绑定记录原样加载。没有单独数据库，不重复保存 Bot 配置。

新增管理 RPC 复用既有管理权限与传输通道：

- `ds-bot.status`：检测状态、公开 Bot 列表、私聊候选与绑定。
- `ds-bot.sessions.list`：只返回已绑定 Bot 的当前 Session ID 和公开头像信息，供侧边栏复用；不返回私聊地址或消息内容。
- `ds-bot.bind`：提交 `botId`、`conversationKey`、`dsBotId`。
- `ds-bot.unbind`：提交 `botId`、`conversationKey`。

保存时重新校验 Bot 可用、所选私聊属于当前账号且双方均未绑定，使用现有会话锁更新运行时映射，再保存独立关联。现有串行写入队列内再次检查唯一性，防止两个页面同时选择同一个 Bot。配置保存失败则恢复原映射，不显示成功。

解绑移除独立关联和该私聊的当前映射，保留已经确认的私聊键（值为 null），以便立即重新绑定。null 不参与会话路由或同步。下一条普通消息按原账号设置创建会话，不删除 Bot、历史记录、投递目标或普通同步配置。删除 IM 账号时清理其绑定与已确认私聊键。

## 会话与消息

IM 发起的消息继续走原渠道权限检查及 Bridge。公共 `askInWorkspaceSession` 发现绑定后解析 DS Bot 当前 Session，不另建普通会话，不修改 IM 账号默认工作目录，不套用默认模型或给 Bot 会话重新命名。

提交消息前再次解析，处理准备附件期间发生的分段；已提交请求不盲目重发。绑定变化及工作区变化沿用已有过期检查。Bot 被删或插件不可用时明确失败，不悄悄回落到普通会话。

桌面发起的消息复用 `SessionSyncCoordinator`、现有投递发送及飞书同步卡片机制。独立绑定在运行时生成同步接收位置，不保存为普通投递目标：

- 查询桌面事件目标时动态解析 Bot 当前 Session，所以即使没有新的 IM 消息也能跟随分段。
- 桌面输入和最终回复沿用原同步规则。
- IM 发起的轮次由原 Bridge 回复，不再次镜像回 IM，也不自动转给绑定同一 Bot 的其他 IM 私聊。
- 发送前重新校验绑定。换段时已在发送流程中的旧段最终回复，可通过 DS Bot 分段记录确认归属。
- 不新增历史补发、编辑撤回、附件同步或持久重试机制。

默认工作目录保持原值，其他未绑定私聊照常工作。私聊中的新建、切换会话或切换工作区操作不能覆盖绑定，应先解除绑定；Bot 会话的模型在 DS Bot 中管理。普通投递目标的创建、编辑、删除和同步开关不修改独立绑定。Bot 改名及换 Session 不掉绑定；插件恢复后重新按稳定 ID 解析。

## 验证

自动测试覆盖插件检测、状态字段过滤、绑定独立存储、版本 3 普通同步迁移、无需投递目标、绑定及解绑不改变投递设置、同步去重、分段跟随、私聊范围、远程 Harness 拒绝及界面头像。原投递设置的同步开关测试继续保留。

真实账号验收按用户指定使用飞书“今天是牢梁”绑定 stepBot、QQ“winBot”绑定 ImBot。必须分别验证 IM 输入进入指定 Bot、回复到达原私聊、桌面输入及回复反向同步，并确认原投递开关可独立操作、默认目录保持不变。单元测试不能代替真实收发验收；其余渠道由公共逻辑与路由测试覆盖，不宣称已经逐一实测。

2026-10-21 实测结果：

| 检查 | 结果 |
| --- | --- |
| 飞书“今天是牢梁” → stepBot | 私聊唯一标记进入 stepBot，飞书收到对应回复 |
| stepBot 桌面 → 飞书 | 桌面输入和完成回复均收到，未观察到重复回复 |
| QQ“winBot” → ImBot | 通过新页面保存绑定，私聊标记进入 ImBot，QQ 收到对应回复 |
| ImBot 桌面 → QQ | 普通投递同步保持关闭，仍收到桌面输入和完成回复 |
| 原投递设置 | 飞书私聊同步开关可关闭、开启，验证后恢复原开启状态，绑定始终保留 |
| 工作目录及身份 | 两个账号的默认目录保持不变，运行时映射与各自 Bot 当前 Session 一致 |
| 页面 | Bot 下拉选项及绑定列表正确显示原始颜色和 logo |

完整 `npm run check` 通过（4361 项测试及包校验）；补充的原同步配置独立操作与准备消息期间分段回归通过，相关定向测试共 45 项。最后的头像兜底及翻译清理已重新构建并通过界面语言测试、包校验。
