# 命令级访问权限方案

日期：2026-11-11。状态：方案与实现说明。需求来源：Issue #95 最初提出的“指令/指令组白名单”诉求，以及 Issue #366 中“全局禁用命令后 /new 也无法执行”的使用反馈。

## 1. 背景

现有访问策略（`src/channels/shared/access-policy.mjs`）已经按 `botId` 保存私聊/群聊的发送者白名单，但每个用户只有 `canExecuteCommands: true | false` 两档，无法回答：

- 白名单用户可以执行哪些插件命令；
- 非白名单用户可以执行哪些插件命令；
- 同一用户私聊允许 ` /help`、群聊只允许 ` /status`；
- 菜单、卡片按钮是否绕过了命令限制。

本方案在原有模型上增加**可选的命令允许列表**，不改变既有访问模式、owner 特权、原子保存和失败关闭语义。`workspaces.json` 仍保持 v2，不新增数据库或依赖。

## 2. 数据模型

### 2.1 用户行

```json
{ "id": "ou_xxx", "canExecuteCommands": true, "allowedCommands": ["help", "status"] }
```

- 省略 `allowedCommands`：`canExecuteCommands: true` 时允许全部命令，保持旧行为。
- 存在 `allowedCommands`：只允许数组中的命令；空数组等于不允许任何命令。
- `canExecuteCommands: false`：禁止所有命令，不允许同时配置非空 `allowedCommands`。

### 2.2 开放模式（默认用户）

```json
{
  "mode": "open",
  "open": {
    "defaultCanExecuteCommands": true,
    "defaultAllowedCommands": ["help", "status"],
    "commandPermissionOverrides": [
      { "id": "ou_admin", "canExecuteCommands": true, "allowedCommands": ["new"] }
    ]
  },
  "allowlist": { "users": [] }
}
```

- `defaultAllowedCommands` 作用于未被 `commandPermissionOverrides` 命中的用户（即通常所说的非白名单用户）。
- 命中覆盖行的用户按自己的 `allowedCommands` 执行。

### 2.3 白名单模式（非白名单用户）

```json
{
  "mode": "allowlist",
  "open": {
    "defaultCanExecuteCommands": false,
    "commandPermissionOverrides": []
  },
  "allowlist": {
    "users": [
      { "id": "ou_alice", "canExecuteCommands": true, "allowedCommands": ["help", "new"] }
    ],
    "nonAllowlistedAllowedCommands": ["help"]
  }
}
```

- `nonAllowlistedAllowedCommands` 省略或空数组：未命中白名单的发送者完全拒绝，保持旧行为。
- 非空时：未命中白名单的发送者仍不能发送普通消息，但可以执行列出的命令（命令级受限访问）。未知命令或未列出命令继续静默拒绝。

## 3. 判定规则

1. 先保留渠道 owner/扫码接入者的特权通道：直接允许普通消息和全部命令，不读取可编辑策略。
2. `allowlist` 模式：
   - 命中白名单用户：普通消息允许；命令按该行 `canExecuteCommands` + `allowedCommands` 判断。
   - 未命中：普通消息拒绝；若为命令且命令 ID 在 `nonAllowlistedAllowedCommands` 中，返回允许（`command-only-allowed`），否则拒绝。
3. `open` 模式：
   - 未命中覆盖行：普通消息允许；命令按 `defaultCanExecuteCommands` + `defaultAllowedCommands` 判断。
   - 命中覆盖行：普通消息允许；命令按该行字段判断。
4. 多个发送者别名匹配多行时，必须所有匹配行都允许该命令；任一行禁止即拒绝。
5. `isCommand: true` 但无法解析出 `commandId` 时，只要存在自定义允许列表就拒绝，避免绕过。

## 4. 命令目录

命令 ID 与主命令名一致，别名归并到同一 ID，例如：

- `workspace`：`/workspace`、`/ws`
- `workspacelist`：`/workspacelist`、`/workspaces`、`/wsl`
- `conv`：`/conv`、`/conversation`、`/thread`
- `sessionlist`：`/sessionlist`、`/sessions`
- `session`：`/session`、`/sess`
- `sessionarchive`：`/sessionarchive`、`/sessarchive`
- `tail`：`/tail`、`/peek`
- `reasoninglist`：`/reasoninglist`、`/reasonings`
- `presetlist`：`/presetlist`、`/presets`
- `menu`：`/menu`、`/m`

完整目录按设置页分组：

| 分组 | 命令 |
| --- | --- |
| 会话管理 | new、fork、reset、compact、clear、history、ls、go、prev、next、drop、title、tail、session、sessionlist、sessionarchive |
| 工作区 | workspace、workspacelist、conv |
| 模型与推理 | models、model、reasoninglist、reasoning |
| 预设与权限 | presetlist、preset、permissionlist、permission |
| 任务控制 | stop、steer、plan、goal |
| 批量输入 | batch、send、cancel |
| 信息 | help、status、version |
| 渠道命令 | menu、repair、watch、unwatch、watchlist、archived |

只有调用方已有的命令识别函数判定为命令后，才解析命令 ID；未知 `/foo` 仍是普通消息，不会因为本功能变成命令。

## 5. 各入口防绕过

访问判定统一发生在副作用之前，并通过实际命令 ID 检查：

- 文字桥接（Telegram、Slack、Discord、WhatsApp、Matrix、Email、iMessage）：`accept()` 从控制文本解析命令 ID。
- 飞书文字、语音转写、卡片按钮和数字菜单：卡片动作按实际目标命令映射；审批/提问按钮仍按普通交互处理，不做命令限制。
- QQ 文字与数字菜单：菜单选择解析出实际 `action.text` 后再检查命令权限。
- 企业微信文字与模板卡片：卡片先解析 `apply`/下拉生成的多条命令，逐条检查后再更新卡片或派发。
- 钉钉文字与菜单卡：菜单回调按实际命令检查。
- 微信、企业微信应用：由共享 `evaluateInboundAccess` 默认解析。
- 工作区卡片按钮：显式按 `workspace` 命令检查。

菜单导航本身按 `menu` 命令检查，但菜单最终执行的业务命令再次检查，不能用导航权限代替业务权限。

## 6. 设置页

- 三态下拉：`全部命令` / `仅指定命令` / `禁止命令`。
- `仅指定命令` 展开按分组排列的命令复选框，支持全选/清空，显示已选数量。
- 开放模式显示“默认命令权限（非白名单用户）”和“命令权限例外（白名单用户）”。
- 白名单模式显示白名单用户行，以及“非白名单用户”区域（禁止执行命令 / 仅可执行指定命令）。
- 仍在页底一次原子保存 `direct + group`，保存成功用服务端快照回填。

## 7. 兼容与失败模式

- 旧策略不含新字段，加载后行为不变；`normalizeAccessPolicy` 继续接受旧 JSON。
- 新字段非法时整份策略拒绝，不写半份配置；损坏策略继续失败关闭。
- 命令 ID 必须属于当前目录，拒绝未知 ID，避免拼写错误造成长期误拒绝或误开放。
- `workspaces.json` 文档版本不变；旧版本代码遇到新字段会拒绝整份策略，回退前应先导出或清空自定义命令配置。
- 不改变 owner 特权、旧 Telegram/WhatsApp 迁移、删除机器人清理策略等既有机制。

## 8. 测试要点

- 共享策略：旧策略不变、三种新字段的校验、开放默认/覆盖、白名单用户/非白名单用户、命令 ID 缺失、别名多行组合。
- 命令目录：别名解析、目录与共享菜单目录一致、非法列表拒绝。
- 设置页：三态切换、命令选择器、保存 payload、非白名单区域。
- 各渠道：文字命令、飞书卡片、QQ 数字菜单、企业微信模板卡片、钉钉菜单、微信文字，验证菜单和卡片不能绕过。
- 全量：`npm run check`。
