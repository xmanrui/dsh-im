# Telegram 交互改版：你会在聊天里看到什么

版本：`5.10.1-wings.2`（个人 fork）。这一版只改「过程怎么显示」和「命令入口」，不碰模型、权限和工作区。

## 1. 三个挡位

| 挡位 | 一轮任务里你看到 | 适合 |
| --- | --- | --- |
| **极简** | 一条「正在处理…」，然后就是答案 | 只想看结果 |
| **标准**（默认） | 一条消息原地动：`⏳ 处理中 · 12 秒 · 2 步`，第二行是最近一次工具（`🔧 bash → npm test`）；模型开始写答案时变 `✍️ 正在整理回复`；结束时收成一行 `✅ 完成 · 12 秒 · 2 步`，随后是答案 | 日常 |
| **全面** | 每条思考、每次工具调用各一行；工具跑完那一行会补上 `· ✓ 0.8s`（失败 `· ⚠️ 失败 0.8s`） | 想看清每一步 |

改版前出厂是「全面」且不带节流，长任务会刷十几条消息——这是这次要治的东西；旧配置里显式打开过「思考过程留痕」的仍然是全面。

## 1.1 随时能停

极简 / 标准挡位的过程消息底部有一个 `⏹ 停止`。点它就会请求停止当前任务，回合结束时按钮自动消失。群里只有**发起这一回合的人**能按，其他人按只会收到提示。

（全面挡位没有过程消息，所以没有按钮；那一档直接发 `/stop`。）

## 2. 怎么切换

- 聊天里发 `/display`：三按钮卡片，点一下就切，卡片原地更新（可连点，不会变死卡）。
- 或直接打 `/display 极简`、`/display 标准`、`/display 全面`。
- DSH 设置页 → IM → Telegram → 会话行为 → 「过程展示挡位」下拉。
- 切换**不会重连机器人**，不影响别的聊天正在跑的任务。

## 3. 命令与菜单的变化

- **`/start` 有了欢迎卡**：新用户点开 bot 时不再把自己的 `/start` 丢给模型，而是收到一张三入口卡（🏠 菜单 / 🎛 显示挡位 / ❓ 帮助），按哪个就打开哪个。
- `/menu` 现在进了 Telegram 原生菜单**第一项**（以前要自己记得打）。
- 群里点命令菜单**真的会有反应**：`/status`、`/menu`、`/display` 这类共享本地命令在群里算「已点名」，不再被「仅 @ 时回复」吞掉（普通聊天仍按原规则）。
- `/status` 卡片多了一行「显示挡位」和一个「🎛 显示挡位」按钮，直接跳到选择器。
- 其它命令没变；`/ws`、`/wsl` 等旧别名仍可输入，只是不在菜单里占位。

## 4. 五分钟验收清单

对着 gpd 那个 bot（`wings_gpd_dsh_bot`）做一遍就够：

1. 点开 bot → 应看到**欢迎卡**（三个按钮），不是模型对 `/start` 的解释。
2. 发一句「跑一下 `echo hi`」→ 过程中只有**一条**消息在变，底部有 `⏹ 停止`；结束后收成一行 `✅ 完成 · N 秒 · M 步`，随后是答案。
3. 发 `/display` → 点「极简」→ 再发一句 → 只看到「正在处理…」和答案。
4. 发 `/display 全面` → 再发一句 → 过程和工具逐条出现，工具跑完那行补 `· ✓ 0.x s`。
5. 发 `/status` → 卡片倒数第二行是「显示挡位：全面」，点按钮能回到选择器。

发现哪里别扭，把那条消息截图发我即可。

## 5. 谁受影响

- 只有 Telegram 渠道的行为变了；WhatsApp / Slack / Discord 等渲染保持原样。
- 卡片回调仍按会话+nonce 校验，别人点你的卡片不会生效。

## 6. 回滚

在 `~/.dsh/profiles/web` 把依赖改回 `file:...5.10.1-wings.1.tgz`（或上游 `5.10.0`），`dsh plugin --profile web install`，重启 dsh-web。备份在同目录 `package.json.bak-*`。
