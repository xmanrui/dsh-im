# Issue #259：默认工作区空目录按需创建修复方案

日期：2026-09-24。代码基线：`d8a0642`，本地版本 `4.27.0`。

来源：[Issue #259](https://github.com/xmanrui/dsh-im/issues/259)。状态：已完成实施、本地回归、构建、Linux / Windows CI 及真实飞书验收；测试临时配置已恢复。实施时工作区已更新至 `8cc3fad`、版本 `4.28.0`，本次未调整版本号。

## 1. 推荐方案

**只在机器人或某个对话实际选用了默认 IM 工作区时创建目录。**

启动时先读取机器人保存的工作区，再决定是否需要创建 `$DSH_HOME/im`。所有机器人及其对话都使用其他目录时，不创建它；有机器人或对话配置为使用它时，照常准备目录。

新机器人选用默认工作区时就创建目录，使菜单、会话列表和第一条消息都能继续正常使用。目录创建集中在现有共享代码中，各渠道只补充已有路径参数。

| 使用场景 | 修复后的行为 |
| --- | --- |
| 启动时没有配置机器人 | 不创建默认 IM 目录 |
| 所有机器人及其对话都配置了其他工作区 | 不创建默认 IM 目录，删除空目录后重启也不重建 |
| 新增机器人并采用默认 IM 工作区 | 初始化该机器人时创建目录 |
| 已有机器人仍使用默认 IM 工作区 | 初始化该机器人时确保目录可用 |
| 机器人使用其他目录，但某个对话显式使用默认 IM 工作区 | 初始化该机器人时确保默认目录可用 |
| 用户通过工作区设置、`/workspace` 或 `/conv` 选择默认 IM 目录 | 选择时按需创建，再沿用现有切换流程 |
| 用户绑定位于默认 IM 目录的已有会话 | 验证会话归属后，恢复会话前确保目录可用 |
| 用户填写一个不存在的普通自定义目录 | 保持原有错误，不自动创建 |

这里的“按需”以实际工作区配置或明确选择为依据。只要仍有机器人或对话选用了默认目录，重启后重建它就是正常行为。

## 2. 为什么采用这个时机

`prepareBotWorkspace()` 当前在加载 `workspaces.json` 之前创建目录，因此即使所有机器人都使用其他工作区，也会留下空目录。

只删除这处创建、一直等到第一次新建会话才创建，会影响现有入口：

- `/sessions` 和菜单会先检查工作区是否存在；目录尚未创建时可能显示“工作区路径不存在”。临时目录验证已确认此行为。
- 工作区切换的校验也要求目录已存在，直接切回默认目录会失败。
- 继续已有会话不一定经过新建会话入口，无法依赖那里的 `mkdir` 覆盖全部路径。

因此把创建动作移到“已确定某个机器人实际使用该目录”的阶段，可以复用现有初始化和目录校验方式，减少对聊天、菜单和会话逻辑的改动。

## 3. 最小实现

### 3.1 默认路径解析只负责返回路径

文件：`src/channels/shared/default-workspace.mjs`。

- 移除 `prepareBotWorkspace()` 内的 `mkdir`。
- 保留函数名、异步接口和返回值 `{ defaultWorkspace, ungroupedWorkspace }`。
- 保留 `dshHome`、环境变量 `DSH_HOME` 和显式 `workspace` 的优先级。
- 增加一个小函数，例如 `ensureImWorkspaceDirectory(workspace, ungroupedWorkspace)`：用现有 `sameWorkspacePath()` 判断，只有目标是该默认 IM 目录时才执行 `mkdir(..., { recursive: true })`。

这个函数不解析机器人配置、不处理会话、不创建其他目录；目录创建错误直接交给调用方现有错误处理。

### 3.2 工作区存储按实际选择准备目录

文件：`src/channels/shared/bot-workspace-store.mjs`。

给 `BotWorkspaceStore` 增加一个可选构造参数 `ungroupedWorkspace`，仅保存在内存。未传该参数时不启用自动创建，以保持其他使用方的行为。

`defaultWorkspace` 与 `ungroupedWorkspace` 必须分开：前者可能是用户指定的普通项目目录，后者才是允许自动创建的默认 IM 目录。

在现有 `ensure(botId)` 中：

1. 优先读取该机器人的已保存工作区；仅在新机器人没有记录时使用传入的初始工作区。
2. 同时检查该机器人已保存的对话专属工作区，覆盖“机器人在项目目录、某个对话在默认 IM 目录”的情况。
3. 在该机器人的现有串行队列中，对这些实际选择调用小函数准备默认目录。普通项目目录直接跳过。
4. 准备失败时不发布新的机器人配置；保留现有参数校验、保存和失败回滚流程。

不在 `load()`、`workspaceFor()`、`conversationWorkspaceFor()` 或列表查询中创建目录。这样读取配置、显示状态不会使无关目录出现，也不会因为失效机器人的残留记录创建目录。

工作区切换时复用同一小函数：

- 在现有绝对路径检查及机器人有效性检查之后、目录存在性校验之前，允许准备明确选中的默认 IM 目录。
- 覆盖 `setWorkspace()`、`applyConversationWorkspaceSwitch()` 以及绑定会话时的工作区校验。
- `/conv clear` 使用机器人当前工作区作为实际目标；只有目标是默认 IM 目录才准备它。
- 保留 `stat`、目录类型检查、`realpath`、会话清理、版本校验和并发切换保护的原有含义；普通自定义目录仍必须存在。

实现上可给 `validateWorkspacePath()` 添加可选的 `ungroupedWorkspace` 参数，在路径格式校验后调用小函数。默认不传参数时，保持该函数当前的严格校验行为。不要在修改配置或清除会话之后才尝试创建目录。

### 3.3 各渠道只透传已算好的路径

在当前调用 `prepareBotWorkspace()` 的生产装配处，把：

```js
new WorkspaceStore(paths.workspaces, { defaultWorkspace })
```

改为：

```js
new WorkspaceStore(paths.workspaces, { defaultWorkspace, ungroupedWorkspace })
```

涉及 `plugin-src/host/channels/` 下的 `feishu`、`dingtalk`、`qq`、`weixin`、`wecom`、`wecom-app`、`slack`、`whatsapp` 和 `shared` 的 `production.mjs`。其中共享装配覆盖 Telegram、Discord、iMessage。

每个入口只是补充一个已有参数，不分别编写创建逻辑。Matrix 等未使用该默认 IM 目录机制的入口保持现有行为，不能通过给构造参数设置隐式全局默认值将它们纳入本次修改。

### 3.4 保留新建会话兜底，补齐已有会话绑定

`src/channels/shared/harness-client.mjs` 的 `createSession()` 已经会在新建默认目录会话前创建目录，直接保留。它能应对初始化后默认目录又被删除的情况。

`src/channels/shared/harness-session-binding.mjs` 的 `adoptRegisteredWorkspaceSession()` 会直接调用会话恢复接口，没有经过上述新建会话方法。这里补一处准备：

- 完成现有会话 ID、归属、会话类型和路径检查后，通过 `client.isUngroupedWorkspace()` 判断最终工作区。
- 仅当它属于默认 IM 目录时，在 `session.create` 调用之前创建目录。
- 保留恢复时传入原 `sessionId` 的逻辑，以及原本的 `cwd` / `workspaceId` 选择，不创建新的替代会话。
- 创建失败就终止本次绑定，原聊天绑定不得被清除。

不改变“默认 IM 目录的会话显示在未分组、普通项目会话按原方式分组”的行为。

## 4. 控制改动范围

核心逻辑集中在默认工作区、工作区存储、已有会话绑定这三个共享模块；生产装配仅补参数。

沿用现有目录创建、路径比较、机器人初始化和错误处理机制。无需新配置开关、后台扫描、依赖或工作区管理服务；`workspaces.json` 的文件格式和已保存路径保持兼容。

已有 `im` 目录不做自动删除或内容迁移。修复解决的是无关目录的自动重建；用户确认是空目录后可自行删除。目录内已有文件必须保留。

## 6. 文档调整与验收

中英文 README 的默认工作区说明同步明确为：

> 新机器人默认使用 `$DSH_HOME/im`（未设置时为 `~/.dsh/im`）。机器人或对话实际选用该目录时自动创建，新会话显示在「未分组」。全部使用其他工作区时，不会仅因启动插件而创建该目录。

验收标准：**用其他工作区的用户不再反复看到多余空目录；使用默认工作区的用户，新增机器人、查看菜单、聊天、切换目录和绑定已有会话保持正常。**

分析阶段已确认：

- 无机器人和已保存自定义工作区两种情况都能复现空目录创建及重载后重建。
- 原有默认工作区及生产装配相关 17 个测试通过；其中“解析默认路径就创建目录”的断言需要随方案调整。
- 跳过启动创建后，新建默认会话本身能准备目录，但完整 `/sessions` 命令在目录缺失时会报错，因此采用按实际机器人配置准备目录的时机。
- 已有会话绑定会把缺失目录直接交给 Host；尚未验证真实 Host 对此的处理，方案在调用前补齐目录准备。
