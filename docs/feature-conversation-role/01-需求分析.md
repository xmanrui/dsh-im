# DSH-IM 会话级角色（Conversation Role）需求分析

> 目标上游版本：基于 xmanrui/dsh-im `v4.9.0`（2026-09 变更集 HEAD `3010535`）。
> 注意：当前用户本地运行的是 `@xmanrui/dsh-im` 3.1.1，两者能力边界不同，本 PR 面向 4.9.0。

## 1. 目标

在不改变“每个机器人只有一个固定 Workspace”安全边界的前提下，让：

- 一个飞书群容纳多个项目机器人；
- 每个项目机器人能使用明确、可切换、可恢复的角色（Agent Preset）；
- 机器人内的角色切换不影响机器人的全局默认 Preset；
- 不同角色拥有独立会话，切回时恢复原上下文。

## 2. 已验证现状（基于 4.9.0 源码）

1. 每个机器人保存一个全局 Workspace（`bot-workspace-store.mjs`）。
2. 每个机器人保存一个全局 Agent Preset（`agentPresets[botId]`），未指定时跟随 Host 默认。
3. Agent Preset 只在创建新 Session 时注入（`createSession`），已有 Session 不变。
4. `/preset`、`/presetlist` 修改机器人全局 Preset（`preset-command.mjs`）。
5. 飞书会话键支持私聊、群聊和话题：
   - 私聊：`p2p:<senderId>`
   - 群聊（无话题）：`group:<chatId>`
   - 群聊+话题：`group:<chatId>:thread:<threadId>`（4.9.0 新增，比 3.1.1 更细粒度）
6. 当前 `/preset` 是机器人级修改，会影响该机器人所有聊天后续的新 Session。

## 3. 用户场景

### 场景 A：一个研发总群容纳多个项目
- `@项目A机器人` 固定进入 Workspace A。
- `@项目B机器人` 固定进入 Workspace B。
- 所有机器人仅在被 @ 时响应，不按项目开群。

### 场景 B：同一项目机器人切换角色
项目 A 机器人需要开发、审查、测试、项目管理等角色，而不是每个角色创建一个机器人。

### 场景 C：切回角色后恢复原会话
开发角色和审查角色不共用 Session。切回开发角色时应恢复原开发 Session。

## 4. 功能需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| R1 | 保留机器人级固定 Workspace | 任何角色都不能改变机器人 Workspace |
| R2 | 角色=Agent Preset 别名 | 不创建第二套 Role 实体；角色 ID 即 Agent Preset ID |
| R3 | 会话级角色覆盖 | `botId + conversationKey → agentPresetOverride` |
| R4 | 角色独立 Session | `conversationKey + rolePresetId → sessionId` |
| R5 | /roles 查询 | 返回可作角色的 Preset、当前角色、对应 Preset，不泄露本机路径 |
| R6 | /role 切换 | 切换当前 bot + conversation 的覆盖角色 |
| R7 | /role --default | 清除覆盖，恢复机器人默认 Preset |
| R8 | 向后兼容 | 无覆盖时行为与 4.9.0 完全一致 |
| R9 | 并发安全 | 切换/创建不能把旧 Session 写回新状态 |
| R10 | 多渠道边界 | 核心放 shared 层；第一版完整接入飞书，不破坏其他渠道 |

## 5. 非功能需求

- 配置文件原子写入、0600 权限。
- role/preset ID 使用受限字符集，拒绝控制字符和任意路径。
- 不上报 App Secret、Token、本机私有路径。
- Workspace 切换时清除该机器人全部角色 Session 映射。
- 删除机器人时删除该机器人角色状态。

## 6. 明确不做

- 不自动创建飞书群或邀请机器人。
- 不允许聊天消息携带任意 Workspace 路径。
- 不实现一个机器人绑定多个 Workspace。
- 不实现完整 Project Registry 或项目—机器人多选矩阵。
- 不自动 commit / push / merge / 部署。

## 7. 已证伪选项

### 直接复用当前 `/preset`
不可作为完整方案：它是机器人级修改，无法为同一机器人不同 conversation 或角色维护独立状态。

### 一个角色一个机器人
可隔离但机器人数量=项目×角色，凭据/权限/升级成本失控。

### 一个通用机器人切换所有项目 Workspace
Workspace 是机器人全局状态，切换会清理 Session 映射，共享群易串项目。

## 8. 开放问题

1. `/role <id>` 是否立即切换并恢复/创建该角色 Session，还是仅设置下一次 `/new` 使用？推荐：立即切换绑定，但下一条普通消息再按角色创建 Session。
2. 角色配置第一版放设置页还是配置文件？推荐两者共用同一 Host API。
3. 角色命令是否推广所有渠道？推荐 shared 核心一次实现，飞书先完成交互卡片，其余渠道至少支持文本命令。

## 9. 推荐最小 PR

实现“机器人固定 Workspace + conversation-scoped role + role-scoped Session”。不引入 Project Registry。
